# Support

Nulx Linux has not released a public beta. No ISO is approved for public testing yet. You can propose documentation corrections using the [contribution guide](CONTRIBUTING.md).

The reporting channels below apply once an official release is available. Suspected problems with release security or verification should always be reported privately.

## Choose the correct channel

- General malfunction: use the [bug report form](https://github.com/Alhasan100/Nulx-Linux-Releases/issues/new?template=bug-report.yml).
- Installer or first-boot failure: use the [installation report form](https://github.com/Alhasan100/Nulx-Linux-Releases/issues/new?template=installation-report.yml).
- Hardware or hypervisor result: use the [compatibility report form](https://github.com/Alhasan100/Nulx-Linux-Releases/issues/new?template=hardware-compatibility.yml).
- Suspected vulnerability: use [private vulnerability reporting](https://github.com/Alhasan100/Nulx-Linux-Releases/security/advisories/new), never a public issue.

For a release report, first [verify your download](docs/VERIFY-DOWNLOAD.md). Include the release tag, verified SHA-256, hardware or VM details, whether the session is live or installed, and the shortest steps that reproduce the issue. Search existing issues and use the newest supported release when practical.

## What support cannot accept

Share only the smallest diagnostic excerpt needed. Follow [Privacy and redaction](docs/PRIVACY-AND-REDACTION.md) before posting logs or screenshots.

Do not upload secrets, credentials, personal information, client data, proprietary target data, unsanitized packet captures, VM disks or raw support bundles. Do not request help attacking a system without authorization.

The project does not yet promise commercial support, response times, or long-term support periods. Those commitments will be documented explicitly if introduced later.
